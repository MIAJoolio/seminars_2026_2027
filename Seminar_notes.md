## 1. Заголовочный файл `.h`

Программу удобно делить на части:

| Файл | Что в нём | Пример |
|------|-----------|--------|
| `.h` | **объявления**: имя функции, параметры, тип результата | `int gcd(int a, int b);` |
| `.c` | **определения**: тела функций | `int gcd(int a, int b) { ... }` |
| тесты `.c` | `main`, который вызывает функции и проверяет ответы | `assert(gcd(12, 18) == 6);` |

- `#include "seminar.h"` — препроцессор просто **вставляет текст** файла на это место. Проверить: `gcc -E test_lab2.c`.
- `""` — файл ищется сначала в папке проекта, `<>` — в системных папках (`<stdio.h>`).
- Защита от повторного подключения:
  ```c
  #ifndef SEMINAR_H
  #define SEMINAR_H
  // объявления
  #endif
  ```
- Собираем **все** `.c` файлы одной командой: `gcc solutions.c test_lab2_blank.c -o seminar_tests`.

Частые ошибки:

| Сообщение | Причина |
|-----------|---------|
| `undefined reference to 'gcd'` | забыли `solutions.c` в команде: объявление есть, тела нет (ошибка линковщика) |
| `implicit declaration of function 'gcd'` | забыли `#include "seminar.h"` |
| `No such file or directory` | опечатка в имени `.h` или файл в другой папке |

## 2. Контракт функции: что должно получиться?

Откройте `seminar.h`:

```c
// Наибольший общий делитель чисел a и b.
int gcd(int a, int b);
int reduce_fraction(int *pnum, int *pden);
int primes_up_to(int n, int **pprimes);
```

Чтобы написать функцию и тесты к ней, этого **мало**. Вопросы, на которые `seminar.h` не отвечает:

- `gcd(0, 5)` — сколько? А `gcd(0, 0)`?
- `gcd(-12, 18)` — ответ `6` или `-6`?
- `reduce_fraction`: что возвращает `int`? Что делать со знаменателем `0`? Где стоит минус у `4/-6`?
- `primes_up_to`: что возвращает `int`? Что будет при `n = 1` или `n = -5`? Входит ли само `n` в ответ?

Ответы — в `seminar_best.h`. **Вывод:** граничные случаи надо договорить до того, как писать код. Хороший комментарий в `.h` — это и есть список граничных тестов.

## 3. Указатели

| Запись | Что значит |
|--------|-----------|
| `int x = 5;` | переменная |
| `&x` | адрес `x` |
| `int *px = &x;` | `px` хранит адрес `x` |
| `*px` | значение по адресу, то есть сама `x` |
| `*px = 10;` | меняем `x` через указатель |
| `int **ppx = &px;` | `ppx` хранит адрес указателя `px` |

**Параметр функции — всегда копия.** Поэтому:

```c
void increment_wrong(int x) { x = x + 1; }    // меняет копию
void increment(int *px)     { *px = *px + 1; } // меняет оригинал

int x = 5;
increment_wrong(x);  // x == 5
increment(&x);       // x == 6
```

Когда что использовать:

| Задача | Как |
|--------|-----|
| функция считает **одно** значение | без указателей, через `return`: `int gcd(int a, int b)` |
| функция меняет **переменную** вызывающего (или две) | `int *`: `reduce_fraction(&num, &den)` |
| функция меняет **указатель** вызывающего (например, создаёт массив) | `int **`: `primes_up_to(10, &primes)` |

Пример указателя на указатель:

```c
void create_array_wrong(int *parr, int n) { parr = malloc(n * sizeof(int)); }  // arr в main останется NULL
void create_array(int **parr, int n)      { *parr = malloc(n * sizeof(int)); } // arr в main изменится

int *arr = NULL;
create_array(&arr, 3);
```

## 4. Тесты

### Как пишем

```c
#include <assert.h>
assert(gcd(12, 18) == 6);  // условие ложно -> программа остановится и покажет строку
```

`assert` останавливается на **первой** ошибке: исправили → запускаем снова.

### Виды тестов

| Вид | Вопрос | Пример |
|-----|--------|--------|
| Функциональные | работает ли на обычных данных? | `gcd(12, 18) == 6` |
| Граничные | что на краях? | `gcd(0, 0)`, `primes_up_to(1)`, дробь `5/0` |
| Стресс | работает ли на тысячах случайных входов? | 100 000 случайных пар для `gcd` |
| На время | достаточно ли быстро? | `primes_up_to(1000000)` быстрее 1 секунды |

### Как придумать граничные тесты

Для каждого параметра спросите:
- что будет при `0`? при `1`? при отрицательном числе?
- что будет, если значения одинаковые?
- что будет на самом краю диапазона? (`n` само простое — входит ли оно в ответ? `i < n` или `i <= n`?)
- что будет при некорректном вводе? Функция должна вернуть ошибку, **а данные остаться прежними**.

### Стресс-тест: как проверить ответ, если он неизвестен

Для случайных `a` и `b` мы не знаем НОД заранее. Но знаем его **свойства**:

```c
int g = gcd(a, b);
assert(a % g == 0 && b % g == 0);  // g делит оба числа
assert(gcd(a / g, b / g) == 1);    // больше общих делителей нет
```

`srand(42)` в начале `main` — случайные числа будут одинаковыми при каждом запуске. Тест **повторяемый**: если упал один раз, упадёт снова, и ошибку можно найти.

### Тест на время

```c
#include <time.h>
clock_t start = clock();
primes_up_to(1000000, &primes);
double seconds = (double)(clock() - start) / CLOCKS_PER_SEC;
assert(seconds < 1.0);
```

Такой тест ловит **неправильный алгоритм**: решение «перебором» даёт верные ответы, но работает слишком долго.

### Хороший тест

- автоматический — запускается одной командой;
- повторяемый — каждый раз одинаковый результат;
- понятный — рядом комментарий, что проверяем;
- один тест — одна проверка: по `assert(num == 3 && den == 4)` не видно, что именно сломалось.

## 5. Задачи

### Задача 1. НОД (без указателей)
`int gcd(int a, int b)` — наибольший общий делитель.

Где пригодится: сократить дробь; выложить пол `a × b` одинаковыми квадратными плитками максимального размера.

Подсказка — алгоритм Евклида: `gcd(a, b) = gcd(b, a % b)`, пока `b` не станет `0`.

| a | b |
|---|---|
| 18 | 12 |
| 12 | 6 |
| 6 | 0 → ответ 6 |

Вопрос: почему перебор всех делителей от `min(a, b)` вниз не пройдёт тест на время для `gcd(2147483647, 2147483646)`?

### Задача 2. Сокращение дроби (с указателями)
`int reduce_fraction(int *pnum, int *pden)` — сократить дробь: `6/8 → 3/4`.

Меняются **две** переменные, через `return` не вернуть — поэтому указатели. Вызов: `reduce_fraction(&num, &den)`.

Функция использует `gcd`. Если `gcd` сломан, упадут и тесты этой задачи — поэтому сначала проверяем `gcd`.

### Задача 3. Простые числа до n (указатель на указатель)
`int primes_up_to(int n, int **pprimes)` — все простые числа от 2 до `n`.

Сколько их будет, заранее неизвестно → массив создаётся **внутри** функции через `malloc`, и его адрес записывается в `*pprimes`. Количество возвращается через `return`.

Решето Эратосфена для `n = 10`:

| Шаг | Вычёркиваем |
|-----|-------------|
| 2 — простое | 4, 6, 8, 10 |
| 3 — простое | 6, 9 |
| 5, 7 — простые | 10 (уже вычеркнуто) |

Ответ: `2, 3, 5, 7`. `calloc` выделяет память, заполненную нулями: «пока ничего не вычеркнуто».

Не забудьте: память, выделенную функцией, освобождает вызывающий — `free(primes)`.

## 6. Мутации: проверяем сами тесты

Тесты прошли — значит, код правильный? Или тесты слабые? Проверим: в `mutants.c` лежит `basic_solutions.c`, но с **одной** маленькой ошибкой. Номера мутаций выбирается флагом `-DMUT=N`:

```
gcc -DMUT=1 mutants.c test_lab2_blank.c -o mut; ./mut
```

- тесты упали → мутация не отразилась на работе функции, тесты хорошие;
- тесты прошли → мутация отразилась на работе функции: допишите тест, который ее исправит.

| MUT | Функция | Что изменилось | Каким `assert` убит? |
|-----|---------|----------------|----------------------|
| 1 | `gcd` | нет модуля | |
| 2 | `gcd` | перебор вместо Евклида | |
| 3 | `reduce_fraction` | при знаменателе 0 возвращает 1 | |
| 4 | `reduce_fraction` | нет проверки знаменателя на 0 | |
| 5 | `reduce_fraction` | минус убирается только из знаменателя | |
| 6 | `reduce_fraction` | `*pden < 0` → `*pden <= 0` | |
| 7 | `primes_up_to` | `n < 2` → `n <= 2` | |
| 8 | `primes_up_to` | `i <= n` → `i < n` | |
| 9 | `primes_up_to` | забыли `free(crossed)` | |
| 10 | `primes_up_to` | `pprimes = &primes` вместо `*pprimes = primes` | |
